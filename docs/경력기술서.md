# 이현재 | 백엔드 개발자 경력기술서

작성 기준: 2026.11.10

## 경력 요약

Java/Spring, Python, C++ 기반으로 CRM 운영 시스템, 외부 서비스 연동, 실시간 안전관제 시스템을 개발했습니다. 데이터 조회·배치 처리부터 장치 데이터 수집, 이벤트 저장, 실시간 전송까지 백엔드의 데이터 처리 흐름을 구현해 왔습니다. 운영 중 발생하는 문제를 로그와 데이터로 확인하고, 처리 구조와 상태 관리 방식을 개선하는 업무를 수행했습니다.

## 주요 기술

- 언어·프레임워크: Java, Spring Boot, Python, FastAPI, C++, Node.js
- 데이터 처리·통신: PostgreSQL, JPA, JdbcTemplate, SQLAlchemy, WebSocket, GraphQL
- 배포·분석 도구: Docker, Azure, NumPy, OpenCV

### 1. 전기차 화재 징후 안전관제 시스템

- 기간: 2025.10 ~ 현재
- 사용 기술: Python, FastAPI, C++, SQLAlchemy, PostgreSQL, asyncio, WebSocket
- 역할: Python 관리 서버 개발, C++ 수집·분석 구조 개선 참여
- [프로젝트 상세](https://hyunganom.github.io/portfolio/thermal-safety/)

열화상 카메라와 가스 센서 데이터를 수집하고, 이상 감지 결과와 발생 이력을 관제 화면에 전달하는 시스템입니다.

**장치 데이터 처리 및 관제 기능 개발**

- 카메라·가스 센서 연동, 감지 이벤트 저장·상태 관리, WebSocket 스트리밍과 외부 장비 연동을 담당했습니다.
- 영상 녹화 및 열화상·가스 데이터의 점검·변환·분석 도구를 개발했습니다.

**실시간 수신과 DB 저장 처리 분리**

- 비동기 이벤트 루프에서 동기 DB 작업을 실행하면서 메시지 수신이 지연되는 문제를 개선했습니다.
- 수신 경로에서는 큐에 작업을 등록하고 별도 작업자가 저장하도록 변경했으며, 데이터 카테고리별로 큐와 작업자를 분리했습니다.

**온도 이상 감지 이력의 조기 종료 오류 개선**

- 이상 판정이 47초간 유지됐지만 DB 이벤트는 11초 만에 종료되는 사례를 확인했습니다.
- 이상 판정 중에는 동일 이벤트를 유지하도록 요구사항을 정의하고, AI를 활용한 원인 분석·수정안·회귀 테스트를 검토했습니다.
- 수정 후 회귀 테스트와 실제 카메라 입력에서 감지 이력이 먼저 종료되지 않는 것을 확인했습니다.

**다중 카메라 처리 구조 설계 참여**

- 다중 카메라 지원, 공유 상태 보호와 작업 충돌 방지를 요구사항으로 정의했습니다.
- 카메라별 처리 순서는 코루틴으로 관리하고 SDK 호출·프레임 수신·분석은 별도 스레드 풀로 분리하는 구조 설계에 참여했습니다.

**카메라 재연결 시 API 지연 문제 분석**

- 카메라 재연결을 직접 실행하고 서버 로그를 점검해 다른 카메라의 API까지 지연되는 현상을 확인했습니다.
- 동기 SDK 연결 대기가 글로벌 락 점유 구간에 포함된 구조와 관련 코드 변경 내용을 검토했습니다.

**열화상 기반 주차 감지 및 판정 방식 개선**

- 열화상 온도맵의 패턴 변화로 주차면 점유 상태와 입출차 시점을 판정하는 아이디어를 제안했습니다.
- 실제 카메라와 현장 설치 환경에서 판정 결과를 확인하고, 온도 변화에 따라 감지 결과가 흔들리는 문제를 개선 요구사항으로 구체화했습니다.
- AI와 알고리즘 검토·구현을 진행하며 온도 차분 방식에서 패턴 유사도와 공간적 온도 변화 보정을 적용하는 방식으로 발전시켰습니다.

**주차 감지 기준 데이터와 초기 학습 개선**

- 관심 영역(ROI)별 기준선을 함께 저장·복원하고, 영역 변경 시 기존 기준선을 무효화해 현재 영역과 맞지 않는 기준선을 사용하는 문제를 개선했습니다.
- 차량이 있는 장면을 임시 기준으로 사용하고, 출차 후 빈 주차면의 기준 데이터를 수집하는 절차를 반영했습니다.
- 학습 품질이 부족하거나 저장에 실패하면 기존 처리 흐름을 유지하면서 재시도하도록 구성했습니다.

**실시간 주차 감지와 녹화 데이터 분석 통합**

- 실시간 입력과 녹화 데이터에 같은 판정 로직을 적용하고, 점수·상태 이력·이벤트 영상을 함께 확인할 수 있도록 개선했습니다.

### 2. 도시 교통신호 최적화 시스템

- 기간: 2025.09 ~ 2025.12
- 사용 기술: Java 21, Spring Boot, WebClient, WebSocket, JPA, JdbcTemplate, PostgreSQL, Apache POI
- 역할: Java/Spring 중계 서버 개발
- [프로젝트 상세](https://hyunganom.github.io/portfolio/city-signal/)

교통신호 학습·최적화를 수행하는 Python 연산 서버와 관리자 웹·Unity 화면을 연결하는 Java/Spring 중계 서버를 개발했습니다.

**학습·최적화 요청 및 실행 이력 관리**

- 요청 메타데이터를 저장하고 WebClient로 Python 서버에 연산을 요청하는 기능을 구현했습니다.
- 작업 ID와 실행 상태를 관리하고, 작업 접수 응답과 장시간 연산의 결과 처리를 분리했습니다.

**실행별 결과 데이터 조회·삭제 구현**

- 실행마다 이름이 달라지는 결과 테이블을 처리하기 위해 정형 메타데이터에는 JPA를, 동적 결과 테이블에는 JdbcTemplate을 적용했습니다.

**시뮬레이션 비교 재생 기능 개발**

- 기존 신호 계획과 최적화 신호 계획의 동일 시점 차량 위치를 WebSocket으로 전송했습니다.
- Unity 화면의 일시정지·재개·시점 이동 요청을 처리했습니다.

**신호 계획 변환 및 분석 보고서 제공**

- 시간대와 Ring·Phase를 구분해 신호 운영 시간을 조회하고 녹색시간을 계산했습니다.
- Apache POI로 시간대별·교차로별 분석 지표와 신호 변경 내역을 Excel로 제공했습니다.

**API 오류 추적 체계 구현**

- 공통 응답과 예외 처리를 구성하고, 응답 및 서버 로그에 traceId를 포함해 요청 단위로 오류를 추적할 수 있도록 했습니다.

## 초안 검토 메모 — 제출본에서 제외

- 연구과제 전체 수행기간은 개인 참여기간과 다르므로, 본인 참여 시작·종료 월을 확인해 기입합니다.
- 카메라 재연결 개선의 최초 제안·구현 주체와 당시 AI 활용 범위는 기존 자료에서 확인이 필요하다고 표시되어 있습니다. 본문에는 확인된 문제 재현·로그 점검·관련 코드 검토 범위를 기재했습니다.
- 다중 카메라 통합 구조는 단일 실제 카메라 및 복제한 논리 채널 시험과 실제 여러 카메라의 통합 검증을 구분합니다. 본문에 실제 다중 장비 운영 검증 완료나 정량 성능 개선을 주장하지 않았습니다.
- 주차 감지의 정확도 향상 수치는 별도로 검증되지 않아 기재하지 않았습니다. 아이디어 제안·현장 검증과 AI 협업 역할을 명시했습니다.
- 본문은 저장소의 이력서와 프로젝트 설명을 바탕으로 작성했습니다. 재직 상태와 진행 중인 업무는 제출 시점에 맞춰 갱신합니다.
