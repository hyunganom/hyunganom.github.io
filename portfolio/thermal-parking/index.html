열화상 카메라 기반 주차면 입출차 감지 알고리즘 설계·구현

바닥에서 천장 방향으로 설치한 열화상 카메라에서 차체 하부가 천장 패턴을 가리는 특성을 이용해 점유 여부를 판단했습니다. 절대 온도 기준의 한계를 NCC 패턴 매칭으로 대체하고, ROI마다 임계값을 다시 잡아야 하는 문제를 σ맵 기반 baseline 예측으로 해결했습니다.

프로젝트 개요

카메라를 바닥에서 천장 방향으로 설치하면, 차량이 없을 때는 천장 패턴이 보이고 차량이 있으면 차체 하부가 시야를 가립니다. 이 프로젝트는 온도 절대값이 아니라 패턴 유사도 변화로 점유 여부를 판정하도록 접근을 바꾼 경험입니다.

열화상은 시간대·계절에 따라 전체 온도가 이동하고, ROI 위치와 질감에 따라 기준선이 달라집니다. 단순 임계값이 아니라 정규화, NCC, 상태 머신, σ맵 기반 baseline 예측을 결합해 안정적인 입출차 이벤트를 만들었습니다.

5세대에 걸친 반복 개선

알고리즘을 한 번에 정하지 않았습니다. 각 세대에서 오판 원인을 데이터로 진단하고, 그 실패 이유가 다음 세대의 설계 근거가 되도록 접근을 바꿔갔습니다.

1. 절대 온도 판정의 실패 → NCC 패턴 매칭

증상

같은 주차면인데 아침과 오후의 판정이 달랐고, 계절이 바뀌자 임계값을 다시 잡아야 했습니다.

원인

온도 평균 임계값은 전역 온도 이동에 그대로 흔들립니다. 분포 너비로 바꿔봐도 실내 천장은 온도가 균일해 차체와 구분되지 않았습니다.

해결

각 프레임에서 평균을 제거하고 표준편차로 정규화한 뒤, 학습 reference와의 패턴 상관도인 NCC를 판정 신호로 채택했습니다.

결과

정규화가 온도의 전역 이동을 상쇄합니다. 전체 온도가 올라가거나 내려가도 패턴이 그대로면 NCC는 그대로입니다. 절대값이 아니라 구조를 보게 된 것이 이 프로젝트의 전환점이었습니다.

def compute_ncc(t, ref_raw, mask):
    """ROI 픽셀에 대한 패턴 상관 — 평균/스케일 정규화로 드리프트 무관"""
    a, b = t[mask], ref_raw[mask]
    sa, sb = a.std(), b.std()
    if sa < 1e-6 or sb < 1e-6:
        return 1.0
    return float((((a - a.mean()) / sa) * ((b - b.mean()) / sb)).mean())

2. 노이즈로 인한 상태 진동 → 상태 머신 + 안정성 게이트

증상

차량이 그대로 서 있는데 점유/빈 상태가 반복적으로 뒤집혀 허위 입출차 이벤트가 쌓였습니다.

원인

단일 프레임의 NCC를 그대로 판정에 쓰면 순간 노이즈 한 번에 상태가 바뀝니다.

해결

EMPTY → ENTERING → PARKED → EXITING 상태 머신을 두고, 전이에 시간 조건과 분산 조건을 함께 요구했습니다. 평활에는 이동평균 대신 median을 썼습니다.

결과

median은 순간 스파이크가 창의 절반을 넘지 않는 한 결과를 바꾸지 못합니다. 이동평균이라면 스파이크 크기에 비례해 값이 끌려갑니다. 실제 입출차 흐름만 이벤트로 남았습니다.

3. ROI마다 임계값을 다시 잡아야 하는 문제 → σ맵 baseline 예측

증상

ROI를 옮기거나 새로 그릴 때마다 임계값을 다시 튜닝해야 했습니다. 빈 상태인데도 NCC가 어떤 ROI는 0.9, 어떤 ROI는 0.6이었습니다.

원인

ROI의 질감과 노이즈 크기가 다르기 때문입니다. 패턴이 뚜렷한 영역은 노이즈가 섞여도 상관도가 높게 유지되지만, 밋밋한 영역은 같은 노이즈에도 상관도가 크게 떨어집니다.

해결

학습 시 픽셀별 시간축 노이즈 σ맵을 함께 저장하고, “이 ROI가 비어 있다면 NCC가 얼마나 나와야 정상인지”를 이론적으로 예측해 baseline B로 삼았습니다. 이후 occ = 1 - NCC / B로 환산합니다.

결과

질감이 강한 ROI와 밋밋한 ROI가 같은 점수 범위로 정렬되어, 하나의 임계값으로 모든 ROI를 판정할 수 있게 됐습니다. ROI를 새로 그려도 튜닝이 필요 없습니다.

baseline B는 어디서 나오는가

B는 실험으로 맞춘 상수가 아니라 유도된 기댓값입니다. 빈 상태의 관측을 reference 패턴과 독립 노이즈의 합으로 놓으면 바로 나옵니다. 

빈 상태 관측:  x = s + n        (s = reference 패턴, n = 독립 노이즈)

  Var(x)   = sv + nv             sv = 공간적 패턴 분산 (신호)
  Cov(x,s) = Var(s) = sv         nv = 시간축 노이즈 분산

  E[NCC] = Cov(x,s) / sqrt( Var(x)·Var(s) )
         = sv / sqrt( (sv + nv)·sv )
         = 1 / sqrt( 1 + nv/sv )      ← 이것이 B
def predict_baseline(ref_raw, sigma_ac, mask):
    """해당 ROI의 빈-상태 NCC 기준선 B 를 σ맵으로 예측."""
    sv = float(ref_raw[mask].var())          # ROI 패턴 세기
    nv = float((sigma_ac[mask] ** 2).mean()) # ROI 시간축 노이즈
    if sv < 1e-6:
        return 1.0
    return float(1.0 / np.sqrt(1.0 + nv / sv))

노이즈 대비 패턴이 강한 ROI(nv/sv 작음)는 B가 1에 가깝고, 밋밋한 ROI는 B가 낮게 예측됩니다. 이 값으로 나누기 때문에 ROI별 차이가 상쇄됩니다. occ는 “빈 상태 기준선 대비 얼마나 무너졌는가”라는 ROI 불변 점수가 됩니다.

σ가 0에 가까우면 B가 발산하므로 NOISE_FLOOR_C = 0.05°C를 하한으로 뒀습니다. 센서 NETD 수준의 물리적 하한이라, 그 아래 값은 측정이 아니라 계산 오차입니다.

σ를 구할 때 공간 평균을 먼저 빼는 이유

stack    = np.stack(frames).astype(np.float32)
ref_raw  = stack.mean(0)                                  # 기준 패턴
stack_ac = stack - stack.mean(axis=(1, 2), keepdims=True) # ← 프레임별 공간 평균 제거
sigma_ac = np.maximum(stack_ac.std(0), NOISE_FLOOR_C)     # 시간축 노이즈

stack_ac 한 줄이 핵심입니다. 이 단계를 빼고 시간축 표준편차를 구하면, 학습 구간 동안 일어난 전역 온도 드리프트가 노이즈로 잡힙니다. σ가 과대평가되면 B가 낮아지고, 그러면 빈 상태인데도 occ가 커져 오탐이 늘어납니다.

프레임마다 공간 평균을 먼저 제거하면 남는 것은 픽셀별 변동뿐입니다. NCC가 정규화로 드리프트를 상쇄하는 것과 같은 원리를 σ 추정에도 적용한 것입니다.

상태 머신

상태 확정에는 두 조건이 모두 필요합니다. 평활된 점수가 임계를 넘는 것만으로는 부족하고, np.std(occ) < 0.06인 안정 상태가 settle_ms 동안 유지돼야 합니다. 값이 임계를 넘었더라도 흔들리고 있다면 아직 판단할 때가 아니라고 본 것입니다.

중간 지대에서는 후보 타이머를 리셋하지 않고 유지합니다. 차량이 들어오는 도중 점수가 잠시 두 임계 사이에 머무는 것은 정상이므로, 여기서 타이머를 초기화하면 입차가 영원히 확정되지 않습니다.

프레임이 3초 이상 끊기거나 타임스탬프가 역행하면 진행 중이던 전이를 되돌립니다. ENTERING → EMPTY, EXITING → PARKED — 즉 불확실할 때는 마지막으로 확정된 상태로 돌아갑니다. 끊긴 구간에서 무슨 일이 있었는지 모르는데 전이를 진행시키는 것이 더 위험하다고 판단했습니다.

배경 갱신 — 제거했다가 조건을 걸어 되살리기

1세대

빈 상태가 일정 시간 지속되면 reference를 무조건 자동 갱신했습니다. 조명·계절 변화에 대응하려는 의도였습니다.

문제

차량이 서서히 들어오는 구간이 "빈 상태"로 오인되면 그 프레임이 reference에 섞입니다. 오염된 기준으로 다음 판정을 하니 오차가 누적됐습니다.

중간

NCC가 온도 변화를 흡수하므로 갱신 없이도 견딜 수 있다고 보고 자동 갱신을 제거했습니다. 오염은 사라졌지만 장기 운용에서 환경 변화가 누적되는 문제가 남았습니다.

현재

조건을 걸어 재도입했습니다. EMPTY 상태이면서 안정 판정이 15초 연속 유지될 때만, α = 0.001의 극단적으로 느린 EMA로 갱신하고 B도 함께 재계산합니다.

효과

세 조건(상태·안정성·지속시간)을 동시에 만족해야 하므로 진입 중인 차량이 섞일 여지가 없습니다. α가 작아 계절 단위 변화만 따라가고 순간 변화는 무시합니다.

if looks_empty and is_stable:
    if self._empty_since_ms is None:
        self._empty_since_ms = ts_ms
    elif (ts_ms - self._empty_since_ms) >= self.cfg.bg_update_wait_ms:
        alpha = self.cfg.bg_update_alpha          # 0.001
        self._ref_raw = (1.0 - alpha) * self._ref_raw + alpha * frame_2d
        self._B = predict_baseline(self._ref_raw, self._sigma_ac, self._mask)
else:
    self._empty_since_ms = None                   # 조건 깨지면 타이머 리셋

시간(ms) 기반 판정

프레임 수 기준으로 검증하면 오프라인 1fps와 실시간 5fps에서 실제 대기 시간이 5배 차이 납니다. 평활 창, 확정 시간, 프레임 갭 판정을 모두 ms 기준으로 바꿔 FPS와 무관하게 동일한 판단이 나오도록 했습니다. 오프라인에서 검증한 파라미터를 실시간에 그대로 쓸 수 있는 근거가 여기에 있습니다.

학습 자기 일관성 검사

라이브 학습 중 사람이나 차량이 지나가면 reference가 오염됩니다. 학습 프레임들을 평균 reference와 각각 NCC 비교해 self_consistency_avg와 self_consistency_min을 계산하고, 기준 이하이면 재학습을 유도했습니다. 최솟값을 함께 보는 이유는, 대부분 깨끗해도 한 프레임만 오염되면 평균으로는 걸러지지 않기 때문입니다.

실내/실외 환경 분리

실외는 EMPTY와 PARKED의 NCC 분리가 명확하지만 실내는 천장 온도가 균일해 분리 폭이 좁습니다. 학습 시 환경을 선택해 npz 메타데이터에 저장하고, 로드할 때 해당 환경의 기준을 적용하도록 분리했습니다.

구성 요소구현 내용
실시간 감지 GUI WebSocket으로 다중 카메라 프레임을 구독하고 학습된 reference(npz)를 자동 로드합니다. 매 프레임 NCC → occ 환산 → median 평활 → 안정성 검증을 거쳐 입출차 이벤트를 CSV·로그로 기록하고 카메라별 카드 UI에 표시합니다. 연결이 끊기면 자동 재구독합니다.
오프라인 분석 GUI tmap 파일을 불러와 캔버스에서 ROI를 직접 그리고, 빈 구간을 지정해 baseline을 학습합니다. 전체 프레임에 알고리즘을 재생해 NCC·occ 시계열을 임계선과 함께 그래프로 그리고, 이벤트 타임라인을 생성합니다. 슬라이더로 프레임 단위 탐색이 가능합니다.
학습 모델 포맷 정규화 reference(ref_raw), σ맵(sigma_ac), ROI 마스크, 환경 정보, 메타데이터를 npz 하나로 저장해 워밍업 없이 즉시 로드합니다.
이벤트 영상 저장 이벤트 발생 시 직전 프레임 버퍼를 함께 묶어 저장합니다. 이벤트 이후만 저장하면 정작 진입 순간이 빠지기 때문입니다.

두 GUI가 같은 검출기 코드를 공유합니다. 오프라인에서 확인한 파라미터가 실시간에서 그대로 재현되므로, 현장에 나가지 않고도 녹화된 tmap으로 튜닝을 끝낼 수 있습니다. 시간 기반 판정으로 바꾼 것이 이 구조를 가능하게 했습니다.

검증 — 예측한 baseline이 실측과 일치하는가

위 화면의 NCC=+0.91   occ=+0.00   B=0.91이 이 알고리즘의 핵심 주장을 그대로 보여줍니다. 주차면이 비어 있는 상태에서 실측 NCC(0.91)가 σ맵으로 예측한 baseline(0.91)과 일치하고, 그 결과 occ = 1 - NCC/B가 0으로 떨어집니다.

앞서 유도한 B = 1/sqrt(1 + nv/sv)는 이론적 기댓값입니다. 그 값이 실제 운영 중 관측값과 맞아떨어진다는 것은, “이 ROI가 비어 있다면 NCC가 얼마여야 하는가”를 학습 데이터만으로 예측할 수 있다는 뜻입니다. ROI를 새로 그려도 임계값을 다시 잡지 않아도 되는 근거가 여기에 있습니다.

참고로 이 화면의 B는 0.91입니다. 만약 절대 NCC 임계값을 쓰던 2세대 방식(빈칸 판정 0.80)이었다면 이 ROI는 문제없이 동작했겠지만, B가 0.6대로 예측되는 밋밋한 ROI에서는 빈 상태조차 점유로 오판했을 것입니다. 정규화가 해결한 것이 바로 이 ROI 의존성입니다.

이벤트 로그

입출차가 반복되는 구간에서 약 1시간 동안 기록된 로그입니다. 입차 시 max_occ는 22~43% 범위에 분포하고, 출차까지의 주차 시간이 함께 기록됩니다. 누적 처리 프레임은 282만 장으로, 장시간 연속 운용에서도 상태 머신이 진동 없이 입차와 출차를 쌍으로 확정하고 있습니다.

이벤트가 ENTER와 EXIT의 쌍으로만 남는 것이 상태 머신과 안정성 게이트가 의도대로 동작한다는 신호입니다. 노이즈로 상태가 진동했다면 같은 구간에 입차·출차가 연달아 여러 번 찍혔을 것입니다.

학습 품질 자기 검사

baseline 학습 시 사용된 프레임 수, 상호 NCC 평균·최솟값, σ 평균·최댓값을 함께 반환합니다. 학습 결과를 저장하기 전에 이 지표를 보여주고, 기준에 못 미치면 다시 학습하도록 유도합니다. 오염된 기준으로 운영에 들어가는 상황을 학습 단계에서 차단하는 것이 목적입니다.

오프라인 재현

녹화된 tmap 구간에 실시간과 동일한 검출기를 적용해 NCC·occ 시계열과 이벤트 타임라인을 생성합니다. 그래프에 점유·빈칸 임계선을 함께 그려, 오판이 났을 때 어느 프레임에서 어떤 조건이 무너졌는지를 직접 확인할 수 있습니다. 파라미터를 바꿔 같은 구간을 다시 돌리면 변경 효과가 바로 비교됩니다.

핵심 성과

이 프로젝트의 핵심은 단일 알고리즘을 한 번에 정한 것이 아니라, 오판 원인을 데이터로 진단하며 접근을 바꿔간 과정입니다. 절대 온도 → NCC 패턴 매칭 → 상태 머신 → σ맵 baseline 예측 → 조건부 배경 갱신으로 다섯 세대에 걸쳐 개선했고, 각 세대의 실패 이유가 다음 설계의 근거가 됐습니다.

기술적으로 가장 의미 있던 지점은 임계값을 튜닝 대상에서 유도 대상으로 바꾼 것입니다. ROI마다 임계값을 다시 잡는 대신, 빈 상태의 NCC 기댓값을 σ맵에서 예측해 그 값으로 정규화했습니다. occ = 1 - NCC/B라는 한 줄이 ROI 의존성을 제거했고, 그 결과 하나의 임계값으로 모든 주차면을 판정할 수 있게 됐습니다.

그리고 그 예측이 맞는지를 실제 운영 화면에서 확인할 수 있었습니다. 빈 상태에서 실측 NCC가 예측 baseline과 일치하고 occ가 0으로 수렴하는 것 (검증 섹션)이, 이 접근이 이론에서 그치지 않았다는 근거입니다.
